### How the installer fetches and verifies the apps

1. The exact file name, URL, size and SHA-256 of every download are pinned in `manifest/apps.lock.json`. The lock is generated by `tools/gen-lock.sh` from GitHub's release metadata, and each SHA-256 is cross-checked against the `SHA256SUMS.txt` file that the authors publish with the release. A mismatch stops the generation. When a release has no such file (or, a known limit of the script today, when fetching it fails), the script warns and uses GitHub's digest alone.
2. Only `https://github.com/...` URLs from the lock are used. The download is made with `curl` (HTTPS only, TLS 1.2 or newer, redirects stay on HTTPS) into a private temporary folder.
3. The file's SHA-256 is compared with the pinned value. If it differs, the file is deleted and that app fails.
4. For a command-line app, the zip is listed first and refused if it has absolute paths, `..` parts or symlinks. Exactly one program named `<app>-cli` is extracted, copied into place atomically, and asked for `--version`, which must report the pinned version. No other downloaded program is run, and the installer makes no change to quarantine or security attributes.
5. For a desktop app (only with `--gui`), the disk image is checked with the same SHA-256 rule, mounted read-only and not browsable, the `.app` is copied out, the image is detached, and the copy must pass `codesign --verify --deep --strict` before it is moved into place. The installer then reports what `spctl --assess` says, so you know whether macOS may ask you to confirm the first launch. An app that is already installed is never overwritten.

A matching checksum shows that you received the file this kit pinned. It is not an audit of the apps.

## Other software the kit uses

The kit relies on tools that are not included: macOS itself (`curl`, `unzip`, `shasum`, `sandbox-exec`, `hdiutil`, `ditto`, `codesign`, Python 3), `jq`, and Claude Code. Each is covered by its own licence. The kit's helper scripts use only the Python standard library and bash.

## The tool snapshots (`data/tools/`)

`data/tools/<app>.json` holds each server's tool names, parameter names and descriptions, and its instructions text, copied verbatim from the running servers at the pinned versions (`make snapshot`). That text is written by the upstream authors and belongs to them; it is included under their licence (MIT OR Apache-2.0, see the table above and the source repositories) so that `doctor.sh` can notice when an installed app's tools change.

## The skills

The files in `skills/` are text written for this kit. Their claims were checked against the apps' own MCP tool lists and instructions, from the pinned versions running on a real machine; anything that could not be checked is marked "(not verified on vX.Y.Z)".
